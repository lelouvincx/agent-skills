# Browser conventions

Choose the workflow for the executor: Amp Desktop Chrome in an orb, or stock agent-browser on the Mac. Load the applicable browser skill before page commands.

## Orbs: Amp-managed Chrome profiles

For website tasks, load `browser-use` and `using-agent-browser`. Use the existing Desktop Chrome so the user can watch or complete sign-in.

1. List profiles with `manage_amp(topic: "profiles", operation: "list")` or `amp profile list`. `agent-browser profiles` inspects local Chrome directories, not Amp's saved profiles.
2. Select the intended profile with `manage_amp` operation `use` or `amp profile use <name>`. Check the current selection with `amp profile status`. Selecting a profile restarts Chrome; select before attaching automation, not during a login flow. Use only profiles the user allows the agent to select. Keep multiplayer disabled unless explicitly authorized.
3. Route through the user's network with `amp net route macbook-network`, then verify `amp net status` and `amp net ping`. If unavailable, report the blocker rather than silently switching to direct Internet. See the network exit-node runbook below.
4. Run `amp orb desktop ensure` and use its reported CDP endpoint. `amp sync` synchronizes repository changes, not browser sessions; `amp sync browser` is not a browser setup step.
5. Attach the orb's installed stock `agent-browser` to Desktop Chrome with a thread-specific namespace, named session, and `--pin-tab`. Do not launch a separate browser.

Example, replacing the namespace with this thread's identity and the port with the reported endpoint:

```bash
AB="/usr/local/bin/agent-browser --namespace <thread-specific-name> --session site --cdp 9222 --pin-tab"
$AB open https://example.com
$AB set viewport 1280 633 2
$AB snapshot -i
```

Repeat the same `AB` definition in every shell call. Another agent must use its own session and tab; it must not drive the parent's tab or change the attached Chrome profile.

### Mac network exit node

`macbook-network` is a standalone `amp net exit-node --id macbook-network` process on Chinh's Mac. It forwards outbound traffic for Chinh's orbs through the Mac's network. It is not a coding runner: `macbook` continues to run local coding threads independently. Routed orbs can reach destinations accessible from the Mac's network.

The persistent service is installed locally, not generated by `amp-runner` or `sync-skills.sh`:

- LaunchAgent: `~/Library/LaunchAgents/com.ampcode.net.macbook-network.plist`
- launchd target: `gui/$(id -u)/com.ampcode.net.macbook-network`
- command: `/usr/bin/caffeinate -s ~/.amp/bin/amp net exit-node --id macbook-network`
- log: `~/.cache/amp/logs/runners/macbook-network.exit-node.log`

The LaunchAgent uses `RunAtLoad` and `KeepAlive` to start at login and restart after exit, with a 10-second throttle. `caffeinate -s` prevents system sleep on AC power, not battery power. The service must be online before an orb can select it; selecting it is an orb-side step, not automatic configuration of every new orb.

Inspect it on the Mac:

```bash
launchctl print "gui/$(id -u)/com.ampcode.net.macbook-network"
tail -30 ~/.cache/amp/logs/runners/macbook-network.exit-node.log
```

When authorized to control the exit node, use `launchctl kickstart -k "gui/$(id -u)/com.ampcode.net.macbook-network"` to restart it. Use `launchctl bootout "gui/$(id -u)/com.ampcode.net.macbook-network"` to stop it for the current login session; the plist remains installed for the next login. Restore a stopped service with `launchctl bootstrap "gui/$(id -u)" ~/Library/LaunchAgents/com.ampcode.net.macbook-network.plist`. These commands affect the exit node, not the `macbook` coding runner.

Verify from the orb before opening a site:

```bash
amp net route macbook-network
amp net status
amp net ping
amp net run -- curl -fsS --max-time 20 -o /dev/null -w 'HTTP %{http_code}\n' https://example.com
amp net status
```

Require a connected `macbook-network` exit node, successful pings, an HTTP 200 response, and an increase in streams through the exit node for the request. A LaunchAgent flag or live coding runner alone is not proof of network sharing. New shells and Chrome windows pick up the route; restart existing programs when needed, or use `amp net run -- <command>` for an explicit routed command. Amp's own control traffic remains on the orb's network.

On 8 November 2026, the `macbook` LaunchAgent included `--share-network`, but the active Amp process did not, and an orb listed no online exit nodes. The runner log recorded an automatic update restart; whether it caused the missing flag was not established. Chinh chose to leave the runner running and approved the independent persistent exit node. After installation, an orb received HTTP 200 through `macbook-network`; Amp reported routed streams and zero direct streams. The connection used WebRTC through a TURN relay. Login startup itself was not retested.

### Sign-in and persistence

Complete sign-in in the selected Desktop Chrome. Pause for the user when a password manager, passkey, CAPTCHA, or other human-only step is required. Keep passwords, OTPs, cookies, and tokens out of snapshots, recordings, logs, and exported files. API credentials do not replace browser passwords.

Verify the intended account and revisit an authenticated page before reporting success. Enable "Remember me" when available. Check `amp profile status` for a saved snapshot; saving a profile is not proof that a site will accept the restored session. Test in a fresh orb when cross-orb persistence is part of the request. Sessions can expire or be revoked.

At each turn's end, stop any recording and run `close` through the same attached session. This disconnects the automation daemon; Desktop Chrome and its login remain. Leave human-only steps open in the Desktop tab and follow `browser-use` for the handoff. Do not export browser state or copy login caches into project snapshots.

## Mac: stock agent-browser

On the Mac, `agent-browser` is the stock CLI that mise installs (`npm:agent-browser`). No wrapper or repository config sits in front of it. Use it with the `agent-browser` skill.

Give each thread its own session with `--session <thread-specific-name>`, and repeat the flag in every shell call. A subagent uses a different session name; it does not drive the parent's session.

For a login that must survive closing the browser, pass `--profile <directory>` with a persistent profile directory and `--headed` so Chinh can complete human-only steps such as passkeys, OTPs or password managers. Tick "Remember me" when the site offers it. Never capture, export or log credentials, one-time codes, passkeys or cookies.

A failed selector, stale reference or wait timeout is a normal page failure: take a new snapshot and retry. After an ambiguous consequential action, such as submit, payment or delete, inspect page and server-visible state before repeating it.

Stock agent-browser silently starts a new browser at `about:blank` when the session's daemon has died or its launch options change. If a command unexpectedly lands on `about:blank`, treat page state and login as lost and reopen explicitly.

Run `close` with the same `--session` at the end of the task. Never use `close --all`, which closes other threads' sessions. Run `agent-browser doctor` when the install or launch misbehaves.

## Testing

Keep repository tests browser-free. Use fixtures and mocks without substituting an unreported browser runtime. Live Chrome validation requires Chinh's approval. Report mock coverage and live coverage separately.

## Timing browser workflows

Resolve the canonical origin and authenticate before measurement. Await the request or UI completion, not chained polling timeouts. Resource Timing finalizes after responses complete. Report setup, client processing and backend time separately.
