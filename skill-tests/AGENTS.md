# Skill test guidance

- Treat this directory as a behavior-regression lab, not an automated test suite.
- Follow `README.md` for the fixture workflow, failure tags, and skill-change criteria.
- Keep fixtures small, realistic, and focused on one failure mode.
- Do not commit routine full transcripts; record durable failures as tags, fixtures, or concise README updates.
- Change a skill only when the failure meets the README criteria, then rerun the failing fixture and one holdout fixture.
